| # | Issue | Choice | Reason |

| D07b-1 | The OAS order statuses have no RETURNED value. | Returns never change `order.status`; return state is exposed only through the return/cancellation APIs. A partial refund therefore cannot turn the order into a fully returned order. | Phase 07 instruction and the OAS enum. |
| D07b-2 | Restocking on returns. | The simulator never adds stock back for a return (SmartOmni Inventory restocks via an idempotent receipt per order/line). Only an approved CANCELLATION restores the simulator's own checkout reservation (existing mechanism, exactly once). | Settled default decision. |
| D07b-3 | One unit in at most one active request. | `AftersaleLine.active` + a PARTIAL UNIQUE INDEX on `orderLineId WHERE active` (raw SQL in the migration). | D07b-4 | Return window. | `aftersale.returnWindowDays` (env `RETURN_WINDOW_DAYS`, default 15), measured on the BUSINESS clock from `deliveredAt`; allowed up to and including delivery + window. | Configurable SIMULATOR/SmartOmni test rule, NOT a verified TikTok policy. |
| D07b-5 | Which buyer cancels are aftersale records. | UNPAID/ON_HOLD buyer cancels stay immediate (no record).
